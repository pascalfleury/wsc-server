#+TITLE: WSC-server — Coding Style and Standards
#+STARTUP: overview shrink

Applies to all project code (=libwsc/=, =src/=, =tests/=, =fuzz/=, =tools/=). Third-party code keeps its own style. Decision: D-25.

* Base style
- [[https://google.github.io/styleguide/cppguide.html][Google C++ Style Guide]], enforced by =.clang-format= (=BasedOnStyle: Google=) and =.clang-tidy= at the repository root. CI fails on formatting or tidy findings.
- Where this file and the Google guide disagree, this file wins; the differences are listed under "Deviations".

| Constants, enumerators | =kPascalCase= (=kLatestValue=)                                                                                                                                                                 |
| Namespaces             | =wsc= for the codec library, =wsc_server= for the server; no =using namespace=; file-local helpers in an unnamed namespace                                                                       |

* Language standard
- The build sets C++23 (=CMAKE_CXX_STANDARD 23=, extensions off). Minimum toolchains: GCC 13 and Clang 18 (with libstdc++ 13) build and pass all checks on Linux; MSVC and Apple Clang minimums are taken from the first green CI run.
- A C++20/23 feature may be used once it compiles on all three CI toolchains (GCC/libstdc++, MSVC, Apple Clang/libc++). Apple's libc++ is usually the one that lags. Until then, use the Abseil equivalent.
- No exceptions, no RTTI (=-fno-exceptions -fno-rtti= and MSVC equivalents); errors are =absl::Status= / =absl::StatusOr<T>=, always checked.

- =[[nodiscard]]= on functions whose result must not be dropped (=absl::Status= already is). =noexcept= on move operations.
- =auto= when the type is obvious from the right-hand side or is noise (iterators, lambdas); spell the type otherwise.

** Coroutines
- Allowed at coarse granularity: one coroutine per long-lived activity (session lifecycle, WebRTC signalling, connect/reconnect loops, discovery cycles, config API work, a transaction's retry/timeout sequence). The frame is allocated once when the activity starts.
- Not allowed per packet or per shaper tick: creating a coroutine there allocates a frame each time and breaks N-01. A long-lived coroutine may loop over packets; it must not spawn one per packet.
- With Asio: =asio::awaitable= with =asio::as_tuple= (error codes, no exceptions), always bound to the component's strand.

** Not used
- =std::expected=: we use =absl::StatusOr= everywhere (D-02); one error type, not two.
- Modules: build-system and tooling support is still uneven across the three platforms.
- Singletons and mutable globals. Static objects must be trivially destructible (Google rule).

** Deviations from the Google guide
- C++23 instead of the guide's C++20 baseline.
- =std::ranges= and views are encouraged, not merely tolerated.
- =std::format= is allowed.

** Data structures
- Above the wire level (routing, adapters, sessions, config), use high-level containers: =absl::flat_hash_map= / =absl::flat_hash_set=, =absl::btree_map= when order matters. They say what the code means.
- Bit manipulation and small fixed lookup arrays belong to low-level packet work (codecs, compatibility matrices, protocol encoders), where the data is fixed and compact.

* Wire data
- Parsers read from =std::span<const uint8_t>= with explicit big-endian load/store helpers; no casting of byte buffers to packed structs.
- Every length and offset is checked before use; a parser returns =absl::StatusOr= and never reads past the span.
- Decoded messages are views into the Frame; they must not outlive it.

* Single responsibility
- A class has one job that fits in one sentence without "and". If the header comment needs "and", split the class.
- A class is one of: a value type (data, no I/O), a parser/encoder (bytes <-> values, no I/O), a policy (decides, owns no sockets), an I/O endpoint (owns a socket or device, decides nothing), or a coordinator that wires the others together. Mixing two of these in one class is the usual sign that it should be split.
- Dependencies are passed to the constructor as interfaces. A class never creates its own collaborators and never reaches for globals; this is what makes it testable with fakes.
- Time comes from an injected clock, never from =absl::Now()= directly inside policy code.
- Threading: a class is either confined to one strand (the default, documented in its header) or explicitly thread-safe. It is never "sometimes locked".

* Modules
- Each directory under =src/= is one CMake library target with its dependencies declared; =libwsc/= depends only on the standard library and Abseil.
- Dependencies point one way, no cycles:
  #+begin_example
  libwsc, memory, core/enums              (no project dependencies beyond these)
     ^
  shaping, routing, feedback              (policies: no sockets, no OS calls)
     ^
  sessions, outputs, translators, discovery, api, platform   (I/O)
     ^
  core/app                                (wires everything; the only place that knows all modules)
  #+end_example
- Modules talk through the interface headers (=OutputAdapter=, =InputTranslator=, =Session=, =FrameSink=). No module includes another module's implementation headers.
- OS-specific code lives only in =src/platform/= and =src/discovery/= backends; =#ifdef= on the OS is not allowed elsewhere.

* Testing
- GoogleTest + GoogleMock, libFuzzer (D-30). Unit tests sit next to the code (=rate_shaper.cc= / =rate_shaper_test.cc=); =tests/= holds integration tests, interop tests and golden packets.
- Every class has a unit test. A change in behaviour comes with a test in the same commit; a bug fix comes with a test that fails without the fix.
- Fakes over mocks: hand-written fakes for =OutputAdapter=, =FrameSink=, =Session= and the clock live in a =testing/= library. Mocks only where the interaction itself is what is being tested.
- No sleeping and no real sockets in unit tests: time is the fake clock, I/O is a fake. Real sockets (loopback) only in =tests/=.
- Coverage, measured on Linux with =llvm-cov= in CI, build fails below the threshold:
  | Scope                                                     | Minimum line coverage                                            |
  |-----------------------------------------------------------+------------------------------------------------------------------|
  | <40>                                                      | <40>                                                             |
  | =libwsc/=                                                 | 90 %                                                             |
  | =src/= except OS backends in =platform/= and =discovery/= | 80 %                                                             |
  | OS backends                                               | no threshold; exercised by the three-OS CI and integration tests |
- Beyond line coverage:
  - a fuzz target for every parser of untrusted bytes (WSC, sACN, Art-Net, OSC, RDM, config JSON);
  - golden-packet round trips for the codec;
  - an allocation-counting test proving N-01 on the forward path;
  - ASan + UBSan on Linux for every test run, TSan for the concurrency tests.
- Test names say what is expected: =TEST(RateShaperTest, RepeatsLastFrameAfterKeepaliveInterval)=.
