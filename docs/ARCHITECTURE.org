#+TITLE: WSC-server — Architecture Overview
#+STARTUP: overview shrink

* Purpose
WSC-server is a gateway that receives Web Show Control (WSC) traffic from consoles and forwards it to show-control protocols (Art-Net, sACN, MIDI, OSC, RDM, ...), and routes feedback from those protocols back to the consoles. Protocol reference: https://github.com/ASLS-org/WSC (v1.1.0).

See [[file:FUNCTIONAL.org][FUNCTIONAL.org]] for what it does, this file for how it is put together, and [[file:PLAN.org][PLAN.org]] for the build-out order.

* Guiding principles
- *One forward path.* Everything that drives devices is WSC by the time it hits the router. Non-WSC inputs (E1.31) are translated into real WSC frames first.
- *Stateless forward routing.* The router only reads the Transport Descriptor carried by each packet (as the WSC spec requires). No route tables.
- *State lives at the edges.* Arbitration and rate shaping state live with the output streams; feedback routing lives in the feedback path; RDM transaction state lives in the RDM module.
- *Not only DMX.* Shaping, arbitration and loss behaviour follow each protocol's delivery model (cyclic, event, transactional; D-21..D-23), not DMX defaults.
- *No steady-state allocation.* Frames come from a pool that grows to fit the traffic and frees idle frames (D-26); once traffic is steady, no allocation happens. Frames are shared (zero-copy) via =std::shared_ptr<const Frame>=.
- *No exceptions.* Errors are =absl::Status= / =absl::StatusOr<T>=.
- *Single-purpose classes*, enums for every "kind of" value, portable code with OS specifics isolated in =src/platform/= and =src/discovery/=.

* Roles of the main interfaces
- =Session= :: a WSC peer. Source on the forward path, sink on the return path.
- =InputTranslator= :: converts a foreign protocol into WSC Frames and hands them to either the forward sink (=SacnToWsc=) or the return sink (=MidiToWsc=, =OscToWsc=). RDM is a single module covering both directions (D-18).
- =OutputAdapter= :: forward sink for one protocol; owns its streams and their shapers; serialises to the wire.
- A physical device (e.g. a MIDI port) may appear both as an =OutputAdapter= and an =InputTranslator=, sharing one device handle.

Supporting pieces:
- =App= (=src/core/app.h=): owns the server ID (=LoadOrCreateServerId=, =core/identity.h=); =Run()= builds the =io_context= and its threads, the =FramePool= with its one-second sweep, the =Router= with the =SacnAdapter= (CID =SacnCid(server ID, "default")=) and the =WsServer=, and runs until its =std::stop_token= is set; =RunInForeground= (=src/platform/foreground.h=) sets it on SIGINT / SIGTERM.
- =Clock= (=src/core/clock.h=): injected wherever time matters (=FramePool=, =SacnAdapter=); =FakeClock= in =testing/= for tests.
- =EventQueue= and =ShapingFor= (=src/shaping/=): the FIFO and the delivery-model policy table, used by event adapters once they exist.

* Concurrency model
- One =asio::io_context= run by a small thread pool.
- One strand per session and per output adapter; shaper timers run on the adapter's strand, so per-stream state needs no locks or atomics.
- Cross-component hand-off is =asio::post(strand, ...)= carrying =shared_ptr<const Frame>=.
- The config API publishes changes by posting onto the owning strands.
